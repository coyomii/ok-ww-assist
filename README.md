# ok-ww-assist · 通用辅助

适用于 [OKWW](https://github.com/ok-oldking/ok-wuthering-waves) 的第三方辅助插件，当前版本 **1.0.1**。一个导入包包含自动重新挑战、自动用药监测和刷4C声骸用药入口。

## 安装 / 更新

需要支持插件清单的 OKWW / ok-script（2.0.15 起）。

1. 停止正在运行的任务，在 OKWW「插件」页添加仓库 `coyomii/ok-ww-assist`。
2. 也可从 [最新 Release](https://github.com/coyomii/ok-ww-assist/releases/latest) 下载 `ok-ww-assist-1.0.1.zip`，选择「导入本地文件」。旧版脚本界面使用本地构建的 `.okscript`，入口为「脚本」→「文件」→「导入脚本」。
3. 更新后完全退出 OKWW（包括托盘）再重启。
4. 需要监测用药时，在「实时触发」页找到「自动用药监测」，打开「启用」开关，并让 OKWW 处于运行状态。首次导入默认关闭。

| 入口 | 用途 |
| --- | --- |
| 通用自动重新挑战 | 自动结算重开、等待加载、短步找 F 开战；用于不能用药的挑战，不包含用药逻辑。挑战次数 0 表示持续。 |
| 自动用药监测 | 独立 TriggerTask，约每 0.40 秒检查一次复苏弹窗；实时触发页提供启用开关。 |
| 刷4C声骸（自动用药） | 继承原生刷4C流程，在本入口内处理用药；刷取参数需在此单独设置。 |

**刷声骸时需要自动用药，请使用「刷4C声骸（自动用药）」。** OKWW 共用一个任务执行器，其他任务或战斗轴的长动作会延后实时触发监测；监测开关无法保证在所有任务内部及时处理弹窗。

内部包 ID 保留 `AutoRechallenge`，便于替换原导入项目并沿用设置。监测开关由框架保存在其专用配置的 `_enabled` 中；更新可能关闭触发任务，更新后请检查开关。“自动使用复活药”也须开启。通用重新挑战的旧药品字段会被框架清理，其余挑战参数保留。刷4C入口使用独立配置。角色与队伍轴需另外安装。

## 用药识别与限制

- 先检查弹窗面板，再对指定区域 OCR；需同时识别复苏标题、恢复意识说明和确认按钮，并用两张新画面确认。
- 默认绿→蓝→紫选择有库存的药，可调整优先级。库存未知时不猜数。
- 灰色确认按钮只等待，默认最多 75 秒；连续两帧确认按钮可用才点击一次。
- 所有药品与本包入口共用至少 60 秒用药间隔，从发送确认时保守计时，专用冷却配置支持重启后继续等待。
- 无药、库存识别失败、等待超时或确认后弹窗未关闭时停止当前任务。

识别针对标准 16:9、三张药品卡片的复苏弹窗。其他宽高比不执行用药点击；其他 16:9 分辨率按比例处理，仍需实机验证。全队覆灭、其他复活窗口、主动打开背包找药和复活后补满血不在本版范围。弹窗关闭与队伍 HUD 恢复不等同于已经识别角色血量恢复；复活后的战斗轴时序也需实机验证。

## 重新挑战

结算按钮支持简繁体「重新挑战」「再次挑战」及英文；说明文字不作为按钮。按钮出现后等待 0.80 秒，两帧确认，点击最小间隔 1.50 秒，最多 4 次，确认离开后不再点击。

出现标准 16:9「挑战成功」结算页时，同时识别居中标题与对应按钮：普通结算点「确认成绩」；首次通关若显示「返回深塔 / 继续挑战」，只点左侧「返回深塔」。两帧确认后松开战斗输入并点击一次。随后如出现询问覆盖成绩的「确认记录」弹窗，点击「取消」；没有弹窗则直接进入楼层页。依次点击「挑战开始」及选角页的「开启挑战」，沿用当前已选角色，等待加载与 HUD 恢复后接回原来的前进、找 F 和战斗流程。

成功也计入挑战次数；0 表示持续循环，达到设定场数时只确认成绩或返回深塔，并在需要时取消覆盖，不开启下一场。每个菜单均需两帧确认且只点击一次；成功页 5 秒未关闭、已点击菜单 15 秒未切换或后续菜单/加载超过配置上限时停止，不重复点击。普通「确认」或其他覆盖弹窗不会触发这些操作。

也可从上述覆盖记录、楼层或已选好角色的选角页启动本任务，继续同一段流程；不会自动更换楼层或选择其他角色。

加载后若出现标准 16:9「环境特性」说明，标题、金色「效果」与正文经两帧确认后按一次 Esc，等待弹窗消失且 HUD 连续两帧恢复；5 秒未恢复就停止。仅在本任务非战斗过渡阶段处理。

HUD 稳定后 W 按 0.20 秒，松开等待 1.00 秒，再检查包含「开始/开启」的 F 提示，找到后只按一次。需要事先朝向机关；不提供复杂寻路。次数统计包括失败，不代表胜场。

## 开发与验证

使用已安装 NumPy、OpenCV 的 Python 环境：

```powershell
python -B build_release.py
python -B -m unittest discover -s tests -p 'test_*.py'
# 使用 OKWW 自带 Python，传入其 working 目录：
python -B devtools/verify_trigger_import.py '<OKWW working 目录>'
```

构建生成 `release/ok-ww-assist-1.0.1.zip` 和 `.okscript`。GitHub Release 仅上传 ZIP，内含四个 Python 文件和 manifest；生成包不提交到源码仓库。可选 `Install.ps1 -WorkingDirectory '<OKWW working 目录>'` 在构建后离线安装，只复制本包并备份本包的旧运行文件。

测试使用合成画面和模拟输入；框架验证在临时目录检查导入、任务分类、真实开关控件与配置持久化。详见 [验证记录](VALIDATION.md)。尚未完成本次发布版本的真实游戏验证。

本项目不修改 OKWW 自带源码或原生任务配置，不安装全局钩子。问题请提交至 [本仓库 Issues](https://github.com/coyomii/ok-ww-assist/issues)。
